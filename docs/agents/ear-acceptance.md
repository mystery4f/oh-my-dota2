# 耳验清单（测试照着读就能做）

这份文件只做一件事：把「只能靠耳朵和眼睛判定」的票写成可执行的步骤。**不需要懂代码**，也不需要看源码。

两类判据：

- **听什么算过**：写到具体到「哪一句该响、哪一句该哑」。
- **听什么算不过**：区分「没生效」（该响的不响 / 该哑的还响）与「生效了但别的地方坏了」（比如静音之后别人也不念了、念到一半被打断）。这一步是这份清单存在的理由——只说「静音生效了」等于没验。

三条硬规矩（对测试同样有效）：

- **不许调用真实模型**。所有出声音的步骤都走本机已有引擎或面板里的「测试模式」（只播不按键）。
- **不许手改 `settings.json`**。所有开关都在面板里点，改文件的值会被应用规范化覆盖，看到的现象就不是你以为的那个配置造成的。
- **判据以日志为准，不看控制台**。本仓的日志在数据目录的 `logs/` 下（`关于 → 诊断` 里有路径）。控制台窗口关掉就没了，日志才是证据。

## #93 逐人静音（对讲里「不念某个人」）

面板位置：`对讲` 页（说给谁听 / 不念谁）。两条写入口子：英雄名一栏、昵称一栏，失焦即存。

### 准备

- 开一局人机或普通局，让 `对局正文` 显示「监听中」。
- 面板 → `对讲` → 朗读开着（不是静音总开关关掉的状态）。
- 先确认基线：什么都不配的时候，队友说话**会被念**。

### 步骤一 · 只哑一个人

- 步骤：在「不念谁」里填上某个队友的英雄名（或他昵称的方括号里那段），等下一次他说话。
- 听到什么算过：**那个人**的发言没有人念；**同一时间别人**的发言照旧被念出来。
- 听到什么算不过：
  - 那个人还在念 → 没生效（确认名字拼的是英雄短名，如 `axe` 而不是 `Ax`）。
  - 那个人不念了，**别人也不念了** → 生效方式错了（像是把总开关关了），这是「生效但别的地方坏了」。
- 日志核对：`logs/voice-chain.jsonl` 里那次跳过应写 `reason: "muted-player"`；若写的是 `"mute"`，说明被当成总开关静音，判不过。

### 步骤二 · 清空名单就恢复

- 步骤：把「不念谁」清空（两栏都清），再让那个人说一句。
- 听到什么算过：同一个人的声音**回来了**，不需要重启应用。
- 听到什么算不过：清空后还是不念 → 名单没真正清（回去看面板里那两栏是不是真空的）。

### 步骤三 · 重启后名单还在

- 步骤：重新填上一个人 → 完全退出应用（托盘退出，不是关窗口）→ 重新打开 → 让那个人说话。
- 听到什么算过：还是只有他不被念，别人正常。
- 听到什么算不过：重启后全体恢复念（名单没落盘）或全体不念（名单读坏了）——两者都要记下来，别只写「不对」。

### 步骤四 · 自己说的话不受影响

- 步骤：自己往对局里打一句（Ctrl+Enter 发出），让朗读念到自己的话。**两个开关状态各做一次**：先把「朗读自己的话」打开做一遍，再关掉做一遍。
- 听到什么算过：开关打开时自己那句被念；关掉时不被念 —— **两次行为必须跟着开关变**。把某人加进静音名单不影响自己的话。
- 听到什么算不过：两次结果一样 → 开关没接上（这比「念错了」更严重，因为意味着那个开关是装饰）。

## #129 同传半双工（自己说话时不要把自己的回声当玩家发言）

背景一句话：应用会用按键/剪贴板把译文发到游戏里，游戏自己会把声音放出来；如果这时麦克风在录，它录到的就是「自己放出来的声音」，再识别一遍就成了荒唐的重复。守卫要做的是：**正在出声的时候，录进来的东西不送识别，并且这件事要记在日志里。**

这张票上次退回的原因值得写进清单里：守卫只装在了主进程那条腿，**公告腿（浮层里播的播报）与同传回放**绕过了它。所以下面**三条腿分别验**，不要一条过了就当全过。

### 准备

- 面板 → `浮层与对局` 里同传/对讲热键记下来（默认 `Alt+Shift+V`）。
- 确认 `关于 → 诊断` 里能看到「自己说话时的回声」这一行（默认应显示「没丢过」或 0）。
- 打开 `logs/voice-chain.jsonl`（示例：`<数据目录>/logs/voice-chain.jsonl`），准备按 `half-duplex-drop` 搜索。

### 腿一 · 公告（浮层播报）

- 步骤：让应用播一条**真公告**（等 GSI 触发神符/肉山/堆野那种；**不要用面板的 `测试模式` 代替** —— 测试模式走主进程 `voice-out.ts`，两处 `notePlayback` 不带腿名，日志会写成 `"stage":"unknown"`，验完分不清是哪条腿过的），在**播报正在响的那一两秒内**按住对讲热键说话。
- 听到什么算过：播报正常播完；你这一句**没有被识别成一句奇怪的话**（不会出现把播报内容当你说的话再翻一遍）。
- 日志核对：看 `stage:"announce"` 的 `half-duplex-drop` 行**多了一行**，或链记录里 `halfDuplex.dropped` 比动手前 **+1**。**不许拿 `total` 当判据** —— `total` 是识别尝试数，只要录了音就涨，没生效也会过。
- 听到什么算不过：播报被别人打断/变调 → 这属于「生效但别的地方坏了」；播报期间你的话仍被完整识别并翻译 → 没生效（这一腿就是上次退回的那一条）。

### 腿二 · 同传出声（译文被送进游戏）

- 步骤：正常打一局，等应用把队友的话译成中文并「送进游戏」出声；在出声那一两秒里按住对讲热键说一句话。
- 听到什么算过：送出去的那句照旧播完；你按住说的那句没有被当成玩家发言识别。
- 日志核对：看 `stage:"echo"` 的 `half-duplex-drop` 行多了一行。「你的话被识别成一句」去哪儿看：`logs/voice-chain.jsonl` 里那次 `stage:"asr"`（或面板 `对讲 → 识别记录` 最新一行）—— 如果那里出现了你按住说的那句，说明没生效。
- 听到什么算不过：两句话叠在一起、或你听到自己的话被念回来 → 没生效。

### 腿三 · 同传回放（面板/浮层里回放刚才那句）

- 前置（缺这一步就无从回放）：**先正常做一次对讲**，让呼出面板的历史里真的有一条可回放的音频；没有这条，腿三不算做过，写「未测到，原因：本局没有生成回放条目」。
- 步骤：在呼出面板里回放那条音频，在回放期间按住对讲热键说话。
- 听到什么算过：回放完整；你说的那句不会被识别。
- 日志核对：看 `stage:"echo"`（回放走的是同一条回放腿）的 `half-duplex-drop` 行多了一行；回放结束时那一行腿名要清掉，不该长期停在 `echo`。

### 哪些已经由探针证明、哪些只能现场看（别把两者混着写）

- **探针已覆盖**（`--half-duplex-probe`，27/27）：守卫入口、公告腿窗口、回放腿窗口、腿名可分（`{"stage":"announce"/"echo","penaltyMs":…,"source":"mic"}`）、播完立刻关窗且腿名清掉、`half-duplex-drop` 真的落进 `logs/voice-chain.jsonl`、链记录带 `halfDuplex:{total,dropped}`。这些**不用在现场重复证明**，现场要证明的是「接线真的通到渲染层」。
- **探针未覆盖，只能现场看**：① 渲染层 → IPC 那一跳（`window.api.voicePlayback(ms, leg)` 是否真过了 preload 到主进程）—— 它的错误形态是「日志里腿名全是 `unknown`」；② 渲染层用 `voicePlayback(0, leg)` 关窗 —— 错误形态是「腿名一直停在 `announce`/`echo` 不消失」。看到这两种就直接判不过，别继续验后面的步骤。
- **`durationMs` 为 null 的情形**：时长没量到时窗口根本不开，日志里一行痕迹都没有。所以现场「没丢过」有两种可能，**必须区分**：先看那次链记录里的 `durationMs` 是不是 null —— 是 null 就写「未记账，不是没丢」，不要写成「通过」。

### 收尾 · 计数看得见

- 步骤：打完一局回 `关于 → 诊断` 看「自己说话时的回声」那一行；**看之前先离开这一页再进来一次**（那一行只在进页面时读一次快照，不自己刷新）。
- 看到什么算过：重进页面后，界面上的数字与 `logs/voice-chain.jsonl` 里 `half-duplex-drop` 的行数**逐个相等**。**不许有误差容忍** —— 差一个就是界面落后了，误差容忍会放过一个落后一整局的数字。
- 看到什么算不过：界面显示「没丢过」但日志里有 `half-duplex-drop` 行 → 界面没接上（**只看控制台不算**，控制台不是证据）。
