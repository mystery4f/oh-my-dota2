# 原型 → 落地：谁的活、怎么过关

`src/renderer/src/prototype/` 是给人看的草图，不是规格。这张文档定义它变成产品代码之前必须过的关，以及谁签字。

## 一句话

**界面票在有人写第一行代码之前，必须由产品经理签字；签字的依据是票面里的五行清单，不是「照原型做」。**

## 谁做什么

- 产品经理（PM）：出原型、写票面五行清单、答澄清问题、签字。
- 实现者：查事实、写 `❓Q / ➡️A`、按签字后的票面写代码；票面缺东西就打回，不许自己补设计。
- 测试：人耳/人眼类验收的唯一关票人（见 `docs/agents/triage-labels.md`）。

## 票面必须有的五行（缺一行就打回）

- **现状位置**：`文件:行`，不是「面板那一页」。没有这一行的票没人能找到要改的地方。
- **真实数据来源**：这一行显示的值从哪来（探针、账本 `train/runs.db`、`logs/*.jsonl`、`settings.*`），以及**测不到时写什么**。原型里的数字一律不算来源。
- **空态与失败态**：没数据、没装、断网、超时、权限拒绝各显示什么。只写「正常长什么样」的票一定做出一个永远绿色的假页面。
- **验收三句**：可观测的现象，不是「看起来对」。能用探针就用探针名；只能人耳/人眼判的，写明交给测试并挂 `ready-for-human`。
- **不许碰的面**：`src/renderer/src/panel/components/primitives.tsx` 的样式、`prototype/**` 本身、以及任何布局/配色/字号/间距改动。

## 三道关

- **第一关：澄清。** 实现者按 `$grill-with-docs` 出一轮 `❓Q`（每条带 `➡️推荐答案`），事实自己查。PM 拍决定。
- **第二关：签字。** PM 在票上留言「签字：可以开工」，并确认五行齐全。没有这句话，代码不写。
- **第三关：交付。** 实现者贴探针输出与门禁（`npm run typecheck`、`npm run lint`、`npm run build`，探针前先 `npm run build`——探针跑的是 `out/` 里的二进制，不 build 就是旧程序）。人耳/人眼类挂 `ready-for-human`，自己不许关票。

## 为什么这么严

原型里有三类东西**一抄就坏**，写在这里是为了让打回有依据：

- 假数据（`412 ms`、`PID 20184`）：写死一个数字，等于把「测不到」变成「永远正常」。
- 假反应（点下载进度自动涨、点测试必成功）：真实路径要处理失败、断点续传、镜像切换，随机成功是反模式。
- 为看得见而放大的绿行：真实面板大多数时候是空、是灰、是「还没测」。
