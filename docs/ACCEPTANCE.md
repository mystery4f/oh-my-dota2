# oh-my-dota2 v3 · 验收清单

> 2026-11 起抓屏 OCR 已整体移除（见 docs/PLAN.md 变更记录）。本清单里凡是「框选聊天区域 / 手动拍照 / OCR 引擎」的步骤都已作废，正文只走 Dota 2 GSI；保留它们只为记录历史踩坑。

> 逐条手动验收用。每条给出「操作 → 期望」，勾选即通过。计划与状态见 [PLAN.md](./PLAN.md)，架构见 [DESIGN.md](./DESIGN.md)。

## 环境准备

- Windows 10/11（x64），Node 20+
- 代理 `http://mcr:4444` 已在设置页填写（访问 mimo 官方端点、HuggingFace、GitHub release 都依赖它）
- 依赖安装（国内源 + Electron 镜像）：

```bash
set "ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/" && npm install --registry=https://registry.npmmirror.com --no-audit --no-fund
```

- 静态校验：`npm run typecheck`、`npm run build` 全绿
- 首次启动后：Overview → provider 选 MiMo → 填 api-key（`sk-` 开头，官方端点用 `api-key` 头）→ 保存 → Test 显示 `OK · Nms`

## 已知限制（不算失败项）

- 录音单次上限 20 秒；whisper base 模型在强噪声/重口音下识别率一般，可后续换 small 模型
- TTS 目前只做面板预览播放，尚未路由到虚拟声卡输出给游戏内队友
- Windows OCR 引擎依赖系统语言包（默认请用 PaddleOCR，无需语言包）
- 俄文/泰文等非拉丁语言依赖模型自身的多语能力，识别可能退化
- 直接 `npx electron out/main/index.js` 运行时脚本目录是 `%APPDATA%/Electron`，与安装版 `%APPDATA%/oh-my-dota2` 是两套 settings
- 闲聊文本没有昵称前缀时，相邻两行中英混排仍可能被并成一条（真实聊天每行都带昵称，风险低）
- 中文英雄昵称（影魔/火女/冰女…）暂未映射成英文缩写，回复英译按字面处理
- GSI 的 cfg 只在游戏启动时读取：配置改完必须重启一次 Dota 2 才生效
- 训练场/人机（`matchid` 为 0）不推 `allplayers`，阵容为空、聊天前缀退回「玩家N」
- OCR 单次识别 0.3–2 秒是天花板，自动模式的实际上限约 0.4 屏/秒；GSI 正文源不受这个限制
- 浮层如果落在聊天捕获区域内会被自己捕获（区域务必只含聊天记录，不含浮层）
- 阵容只做「谁是谁」，不做派对检测（GSI 不提供组队信息）

## 快速排查

| 现象 | 先查 |
|---|---|
| overlay 没内容 | Capture 页是否 Start、区域是否框到聊天记录、`截图诊断` 是否识别出文本 |
