# 训练残留的统一回收：启动时只留一份能用的

状态：已接受（2026-11-09）

## 背景

训练相关的磁盘有三处会一直长大，`asr-ft-run-retention.md` 只管了其中一处：

- 导出产物 `data/asr-ft-onnx/ft-<stamp>/`：每轮一份，qwen3 一份 7.2 GB（fp32 外置权重 + int8）。它只在下一次换模时被当成「待转正」读一次，转正之后就没人看了。实测 2026-11-09 积了 24 个目录、**18 GB**，其中一半是导出腿被杀留下的半成品（0 字节或只有一两个文件）。
- 中断轮的 run 目录 `data/asr-ft-runs/ft-<stamp>/`：`pruneAsrFtRunDirs()` 只在换模成功后跑。中断/失败的那几轮永远等不到下一次成功，一份 4.4 GB 就一直躺着。实测积了两份。
- 换模窗口：`active → .bak` 与 `next → active` 之间被强杀，现役目录会短暂不存在。启动对账不查这里。

## 决定

两条回收都放在**启动对账**（`reconcileTrainState()`）里，而不是每轮 `finish()` 之后：

- 训练期间的写入不经过别的进程，不存在「现在没人写」的歧义；启动那一刻保证没有任何 python 子进程在跑。
- 回收是幂等的，多跑一次没有副作用；放在 `finish()` 里反而要区分五种终态。

具体口径：

- 导出产物：`asr-ft-onnx/` 下**只留最新那份产物齐全的**，其余（旧的齐全目录 + 所有半成品）删。判据是 `holdsExport()`，与 `lastExportDir()` 同源，所以删完 `lastExportDir()` 仍然指向留下的那份。
- run 目录：按 `started_at` 从新到旧扫，**留第一份还能接着训的**，其余删。判据 `holdsResumeWeight()`：有 `checkpoint-N` 目录（qwen3）或 `model.pt*` 文件（funasr）——就是 `findIncrementalSource()` 认的那两样。删掉的同时把该轮 `artifacts.runDir` 置空，行与 `metrics` 快照保留。
- 保留份数一律是 1，不再叠加「上一轮起点」：能接着训的那份本身就是起点。

## 后果

- 一次启动最多回收 10–18 GB（实测口径）；代价是**不能从更早的几轮再导出**——要重导就重训一轮。
- 增量链变短：只能从最新那份有权的 checkpoint 续。若要保住更早的练法，先在 `asr-ft-runs/` 外面自己拷一份。
- 判据比 `findIncrementalSource()` 松一档（不看账本谱系）：算不出谱系时也留得住目录，宁可多占 4.4 GB 也不误删起点。这条是刻意的，回收可以少收，不能多收。
- 换模窗口仍未处理：启动对账目前不修复「现役目录消失、`.bak` 与 `.next` 都在」的状态。

## 仍然不做

- 不做手动清理按钮：面板里加一个「清理磁盘」等于给了用户一个删错就重训一小时的开关。
- 不动 `TRAIN_RUN_KEEP = 200`（数据库行保留量）与 `asr-ft-env/`（环境，重装要下几个 GB）。
- 不在训练过程中回收：中断恢复靠的就是那些目录。
