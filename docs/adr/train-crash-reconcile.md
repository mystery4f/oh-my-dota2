# 训练被中断后的收尾与对账

- 状态：已接受
- 日期：2026-11-09
- 相关：`docs/adr/asr-ft-run-retention.md`、`docs/adr/asr-train-rewrite.md`

## 背景

训练是一个 python 子进程。Windows 上父进程退出不会带走它，而它写下的状态分三处：

- `runs.db` 里一行 `status = 'running'`（开训即落盘，收场才改终态）；
- `asr-ft-runs/<stem>` 目录（checkpoint，几 GB）；
- `<模型目录>.next`（训练前抄进去的接续权重，或导出产物，一次增量 4.4 GB）。

2026-11-09 实测两种中断：用户点退出时训练还在跑；以及训练中途把应用整个退掉。前者留下跑到天亮的孤儿 python 进程，后者留下一条永久的 `running` 行（面板永远显示「训练中」，开始训练的按钮永远灰着）和一个 4.4 GB 的 `.next`。

## 决定

- 正常退出：`will-quit` 里调 `trainManagerIfStarted()?.shutdown()`。它 `taskkill /T /F` 杀进程树，把 `running` 的行改成 `failed`（错误文案「应用退出，训练被中断（这一轮没有跑完）」），并清掉推理占用标志。**不**走 `finish()`：那里会广播快照、发系统通知、把朗读拉回来，而退出途中窗口正在销毁。
- 启动对账：`reconcileTrainState()` 在 `app.whenReady()` 里跑一次，兜住强杀/崩溃/断电。
  - 库里任何 `running` 的行改成 `failed`（错误文案「上次训练时应用退出了，这一轮没有跑完」）。进程已经没了，`running` 一定是假话。
  - `data/asr-models/*.next`：含任一件导出产物（三个引擎产物名的并集）就保留——那是「导出已完成、换模前那一刻退出」的成品；一件都没有就整目录删掉，那是可以重造一次的接续中间件。
  - 单例没被创建过就什么都不做；对账本身幂等。
- 脚本以仓库为准：`resolveAsrFtTrainRequest` 在开训前用 `copyAsrFtScripts(envRoot)` 把 `resources/asr-ft/*` 刷进环境。环境里的副本是「装好就不再动」的，脚本改了不刷新等于没改——2026-11-09 就出过一次：一份补丁只存在于环境副本里，重装环境后凭空消失，增量续训重新报 `upgrade torch to at least v2.6`。刷新失败直接拒启动，不跑旧脚本。

## 后果

- 面板不再出现「停在训练中、点不动」的僵局；一次中断最多留一个 4.4 GB 的 `.next`，下次启动清掉。
- 换模前一刻退出会留下 `.next` 成品，启动时不删；它没有对应的「应用」按钮（见 `asr-train-rewrite` 的自动转正），要救回来得手动把它换成现役目录。
- 刷新脚本这件事让「环境里跑的是什么」总等于仓库里的那份，也意味着手改环境副本会在下次开训被覆盖。

## 仍然不做

- 不做训练进度续跑（崩溃后从 checkpoint 自动续）：续跑要重新算账本、验证集与 lr，判断错一次就是一小时白烧，先交给人点。
- 不删 `asr-ft-runs/<stem>`：那是训练副产物，回收规则在 `asr-ft-run-retention` 里。
