# ADR：看一眼画面——用户按下才截图，模型名决定能不能看

- 状态：已采纳（#135）
- 日期：2026-11-21

## 背景

`providers/openai-compat.ts` 只会发文本：`ChatMessage.content` 是字符串。票面（#135）要的是「按一次热键，截当前这一帧，问能看图的模型，答案落在呼出面板」，并且把三条边界钉死：图片不落盘、不能看图时说人话、截不到画面要给消息而不是空面板。

## 决定

- `ChatMessage.content` 扩成 `string | ChatContentPart[]`，图片是 `{type:'image_url', image_url:{url: data URL}}`。**只收 data URL**：模型侧本来也不吃磁盘路径，而路径还会把本机目录结构发出去。
- 截屏用 `desktopCapturer`（一次一帧），不用常驻流：这东西一分钟调一次都嫌多，建流还要管生命周期。第一帧为空重试一次再报错——桌面刚切、会话没解锁时第一帧空是常态。
- 能不能看图由**模型名启发式**判（`isVisionModel`，认 vl / vision / omni / gpt-4o / claude / gemini 这类字样）。判不准时的文案是「按名字看它不收图，去对话页换一个能看图的」，不是「这个模型不支持图片」——名字不是能力查询，说死就是撒谎。
- 一次请求的形状（一条消息、两块内容）由纯函数 `buildVisionMessages()` 产出，探针直接断言它，不花一次真调用。
- 热键（`visionAsk`，默认 `Alt+Shift+G`）先打开呼出面板再截图，结果广播回渲染层（`vision:result`）并落到「看一眼」页；失败另给浮层一行提示——热键这条路没人接返回值。

## 不这样做的地方

- 不做后台/逐帧截图：那不是功能，是账单炸弹，也会把「我在看你」变成常态。
- 不写任何缓存目录：截图不进磁盘、不进 `logs/`，探针用「logs 目录前后一致」钉住这一条。
- 不猜模型能力做自动切换：换模型是用户的决定，我们只给判断依据。

## 验收

- `npm run probe -- --vision-probe`：15 条断言（payload 形状、提示词要点、名字判据正反例、三种拒因、两行文案、截图不进 logs）。
- 拿不到桌面（无显示器/会话锁着）时探针记 `captured: skipped: …` 并且那一条断言仍然通过——因为「截不到时给的是这句话」本身就是被要求的行为。

## 后果

- 新增「能看图的模型」只需改 `VISION_MODEL_HINTS` 一条正则；反过来，名字里没有这些字样的视觉模型会被误判为不能看，此时用户看到的是一句可以照做的指示，而不是坏掉的功能。
- `ChatMessage.content` 变成联合类型后，任何按字符串处理的调用方（比如拼接历史）都必须显式判 `typeof content === 'string'`，否则类型检查会拦下来。
