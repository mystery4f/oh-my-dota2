# ADR：训练目录只留增量起点——换模成功后才清

- 状态：已接受（2026-11-09）
- 关联：`docs/adr/asr-train-rewrite.md`（增量微调的起点定义）、`docs/adr/train-manager-orchestrator.md`（训练收场的终态路径）

## 背景

每轮 ASR 微调在 `<userData>/asr-ft-runs/ft-<时间戳>/` 留下一整套权重：`model.pt`、`model.pt.best`，外加 `keep_nbest_models=4` 个 `model.pt.epN` checkpoint。实测一轮 41 条 / 15 epoch 是 15 GB。

数据库有 `TRAIN_RUN_KEEP = 200` 行上限（`pruneTrainRuns()`），目录却是只增不减。按 7 分钟一轮的速度，重训十几次就把盘吃满。

但目录不能随手删：增量训练的起点不是「已应用的模型目录」，而是 `findIncrementalSource()` 在历史上某一轮 run 的 `artifacts.runDir` 里挑出的 `model.pt.best`（或 qwen3 的 `checkpoint-<步数>`），并且要求那一轮的 `dataset.jsonl` 与当前账本谱系对得上。删错一份，「接着上次权重」就变成「请先做一次从底模重训」。

## 决定

- **时机**：只有一轮训练「导出成功 **且** 换模成功」之后才清理。开训前不清理——失败轮留下的日志与半截权重是排查时唯一的现场。
- **保留两份**：刚结束的这轮，加上 `findIncrementalSource()` 给出的下一轮增量起点（两者常常是同一份，那就只留一份）。
- **前置条件**：起点算得出来才动手。权重文件末尾完整性检查不过、或账本谱系对不上，就一个字节都不删。
- **记录处理**：删目录时把该行的 `artifacts.runDir` 置空，不删行。历史（哪一轮、几条数据、指标）仍在，只是不再指向不存在的路径；面板的「训练历史」照旧显示。
- **不越界**：只删 `asr-ft-runs/<stem>` 这一层的子目录，别处的路径（老数据、手工目录）不碰。
- **不做手动清理按钮**：面板的既有规矩是「设置即时生效、没有保存按钮」，清理是换模的副作用，不该变成用户要记得点的动作。
- `TRAIN_RUN_KEEP = 200` 不动：它管的是历史行，与磁盘占用无关。

## 后果

- 稳态磁盘占用约 15–30 GB（一份或两份目录），不再随训练次数线性增长。
- 被清掉目录的 run 行会失去「指标从 run 目录回读」的能力，但 `runs.metrics` 在收场时已经抄了一份快照，历史里的数字不会变成空白。
- 失败轮只要还没被下一轮成功换模顶掉，就一直留着；顶掉之后它随即被清理——这正是「现场是给当下排查用的」。
- 若下一轮的增量起点算不出来（例如账本被改），清理直接放弃，磁盘回到无上限增长——宁可占盘，不可删错。

## 仍然不做

- 不按时间自动清理（「30 天前的删掉」这类规则）。
- 不清理导出目录 `asr-ft-onnx/`（体积小，且换模后的现役模型就在那里）。
- 不为磁盘占用做面板提示或报警。
