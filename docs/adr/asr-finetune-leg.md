# ADR：识别微调成为正式训练腿，热词只管「能提示的引擎」
- 状态：已接受（2026-11-09）
- 取代：`docs/adr/asr-hotwords-not-finetune.md`（「识别个性化只走热词注入、微调记档不排期」这一条）
- 关联：`docs/adr/train-manager-orchestrator.md`（编排器定位不变）、`docs/adr/train-run-model-and-panel-pages.md`（训练记录进 SQLite 的存储决定）、`docs/DESIGN-asr-engine-table.md`（引擎表与两条微调腿的落地细节）

## 背景

2026-11-01 的 ADR 把识别个性化定为「热词注入，不做微调」，微调只留触发条件；11-02 与 11-08 两次更正先后推翻「Qwen3 不可微调」并把候选模型换成 paraformer，但主线仍是「热词优先、微调记档」。此后一轮完整落地（tickets #59–#66）把微调做成了产品功能：SQLite 训练记录与数据集账本、增量微调、待训统计、开训前估时、纠错样本回喂、训练期推理互斥，识别训练页也已有两条腿。继续按旧 ADR 描述现状会误导使用者（「微调不做」），所以需要一条新决定取代它。

## 决定

- **微调是一等训练腿**，与 GV 的两腿同级：引擎表 `ASR_ENGINES[*].finetune` 声明 trainer、训练/导出脚本、底模、产物与每步耗时。现在两条：`qwen3`（`qwen3_asr_sft.py` + ONNX 导出）与 `paraformer`（`funasr.bin.train` + `asr-ft-export-funasr.py`）。加引擎 = 引擎表加一行 + worker 一个适配器，不在调用点分支。
- **两种开训形态由一条纯函数决定**（`planFtTuning`）：从底模重训（默认轮数/学习率）与增量微调（学习率 1e-5，目标约 300 步：funasr 直接钳轮数 2–12，qwen3 从上个 checkpoint 的步数再补 200 步折算）。增量接的是**上一轮的 PyTorch 权重**（funasr `++init_param`、qwen3 `--resume_from`）；导出的 int8 ONNX 只能推理，不能续训。
- **增量资格看数据身份，不看时间**：上一轮 run 打包时的逐条录音指纹必须与当前账本逐条一致，且接续点仍在（funasr：权重文件优先 `model.pt.avg1`、其次 `model.pt.best`、`model.pt`；qwen3：编号最大的 `checkpoint-<步数>` 目录）；重录或删除过录音就拒绝，并提示先做一次从底模重训。
- **底模永久保留**：训练从底模或上一轮权重开始，导出时用底模 + 训练权重建图并附 sherpa 元数据/tokens；底模本身不被覆盖，微调产物在模型注册表里是独立的 `fine-tuned` 条目。
- **转正才生效**：导出到现役目录名加 `.next`（`qwen3-asr.next` / `paraformer-zh.next`）→ 现役进回滚槽（`.bak`）→ 换上新模型；回滚把槽里的换回来。转正/回滚步骤是数据（`swap` 计划），不是每个引擎一段代码。
- **热词注入保留，但只给支持提示的引擎**（现在只有 Qwen3）。Paraformer 忽略热词（sherpa 只对 transducer 类做热词），它的个性化走微调；两条路线并存，不是二选一。
- **纠错回路同时喂两边**：≥2 字的差异片段并入热词表（即时生效），`asrCorrectionsToDataset` 打开时把改对的那句连同原始录音留成纠错样本 `G01-Tnn`（下一轮训练生效）。
- **开训前先说清代价**：待训条数、覆盖比例、估时（步数 + 分钟，未测过的形状明确标成估算）都由纯函数算出，面板只显示；训练期 GV 推理走推理互斥让路。

## 后果

- 训练记录与数据集账本是 `train/runs.db` 两件事的唯一来源（run 行 + 每条录音的 run_id）；run 目录里仍留 checkpoint 与 `run.json`，那是训练器副产物，不进库，也不作为账本依据。
- 增量微调便宜（约 300 步），但它把「数据集改过」变成一种需要显式处理的失败：重录/删除会让上一轮权重不再可接。
- Paraformer 不出标点，识别结果没有句读；补标点模型仍不在本轮范围。
- 精度证据只有一次非盲测：Qwen3 底模 6.27% CER → 微调后 0.63%（G14），Paraformer 17.79% → 11.66%（30 轮、4060 Laptop 约 6 分钟，仍偏欠拟合）。G15 同时被用来挑 checkpoint，所以它不是盲测集，任何「绝对提升」的说法都要带这个前提。

## 仍然不做（本轮边界）

- 不给不出标点的引擎加标点模型。
- 不加第三个引擎，也不恢复 whisper；引擎表就两行。
- 不在攒够 N 条新录音后自动开训：应用只报告「待训多少」，开训仍是人的动作。
- 不做多任务队列 / GPU 调度：仍是一个训练任务 + 推理互斥。
- 不把 settings、翻译会话、音色包迁进 SQLite。
- 不做盲测协议，也不为此新录一批数据。
