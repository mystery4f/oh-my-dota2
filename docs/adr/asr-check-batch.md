# 全量识别比对：一个按钮加一个弹层，结果不落库

## 背景

训练完最要紧的问题是「现在这套模型到底认不认得我录的那些句子」，而面板此前只能一次测一句（「识别测试」）。
要判断该不该继续录、该不该再训一轮，需要的是**整库**的答案：83 条里错了几条、错在哪些句子。
这件事此前只能在仓库里写临时脚本做（`.tmp/asr-cmp.mjs` 那类），用户看不到。

## 决定

- 位置：识别训练页「数据」步，「打包数据集」之后加一行「全量识别比对」，点开是弹层（`Modal`）。
  不加第五个步骤、不新开页面——它读的是数据、用的是现役模型，属于数据步的一次体检。
- 模型：**现役模型**（`asrActiveModel`），不跟随训练目标。要问的是「现在识别得怎么样」，
  和下一轮要训哪个引擎无关。
- 范围：账本里全部条目（最新修订、带标签的），串行识别，带「停止」。
- 判定：先**归一化**（去标点、去空白、转小写）再算编辑距离。qwen3 输出带标点、paraformer 不输出，
  逐字严格比会让换引擎的每次比对都全错。差 1 字或错字占比 ≤15% 记「差一点」，其余记「明显错」。
- 展示：顶部一行汇总（共 N / 一致 / 差一点 / 明显错 / 耗时），默认只列不一致，带「显示全部」开关；
  每行给 key、原文、识别结果，原文与结果都原样显示。
- 生命周期：状态只在主进程内存里（`src/main/services/train/asr-check.ts`），关掉弹层就丢。
  重跑一次约一分钟，不值得落库，也不该成为又一份需要清理的产物。

## 后果

- 判定口径只有一份（`src/shared/train/asr-check.ts`），探针与面板读同一份，不会各算一套。
- 识别失败（模型没就绪、worker 崩）整轮停下并显示原因，不把失败当成「全错」记进清单。
- 录音文件丢了的条目仍然进清单（标「录音文件丢了」），因为静默跳过会让人误以为那条没问题。
- 结果不落库，所以「上一轮比这一轮好多少」无法在面板里对比；需要留证据时复制清单文本。

## 仍然不做

- 不做逐字高亮的字符级 diff（清单里给的是两整行，够看）。
- 不做「边跑边写库」「后台跑、关弹层继续跑」——关掉就是放弃。
- 不替代「识别测试」（那是单句试听，带录音回放）。
