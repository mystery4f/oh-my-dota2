# ADR：浮层可读性——三档字号、AA 对比度、状态不只靠颜色

- 状态：已采纳（#100）
- 日期：2026-11-21

## 背景

浮层的文字大小原本只有一套（`.orig` 12px / `.trans` 13px / 角标 10px），谁都觉得小就只能自己想办法；颜色直接写在 `overlay.css` 里，没有任何一处能被检查，所以「对比度够不够」「色弱能不能分清已播和未播」这两个问题从来没有答案——它们既不在类型里，也不在探针里，只在评审时的肉眼感觉里。

票面（#100）要求三件事：三档字号；调色板对色盲安全、文字对达到 AA；任何状态都不能只靠颜色表达。

## 决定

- 字号三档（`small` / `normal` / `large`）落在 `src/shared/overlay-a11y.ts` 的 `FONT_SCALE` 一张表里，CSS 侧只放四个变量 `--ov-fs-mini/small/body/title`，由根节点 `data-font` 切换。`normal` 与改动前逐像素一致 —— 老用户升级后一个像素都不动。
- 每对文字的对比度写进同一张表（`OVERLAY_TEXT_PAIRS`），探针 `--overlay-a11y-probe` 逐对算 WCAG 比值并要求 ≥ 4.5。
- 「状态不只靠颜色」写成一列 `OVERLAY_STATE_MARKS`：每个用颜色表达状态的地方必须还有一个颜色以外的标记。落地的两处：`.spoken.ok` 加 `✓ `、`.spoken.err` 加 `✕ `（`::before`）；阶段行的警告文案加 `⚠ ` 前缀（在 `stageLine` 里拼，所以在灰度截图、色弱、以及只有文字的复制粘贴里都是同一句话）。
- `check:pure` 额外守一道漂移：`overlay.css` 里不许再出现字面量 `font-size`，四个变量的三组值与 `overlayFontScale()` 必须逐个相等。

## 换算基准：为什么是「行底色叠在纯黑上」

浮层是透明窗口，背后是实况游戏画面，任何颜色都可能出现在字下面。真正可算的基准只有一个：行底色（默认 `rgba(12,10,9,0.34)`）叠在纯黑上。亮场景靠 `text-shadow: 0 1px 3px rgba(0,0,0,0.9)` 兜——那一点没法在离屏算出来。

所以探针给的是「在自家底色上达标」，不是「在任何画面上都看得清」。这个区别必须写下来：把 AA 通过当成后者，是拿一个真数字去支撑一个假的结论。

## 不这样做的地方

- 不做全量 UI zoom：`zoom` 会把 padding、圆角、图标一起放大，浮层是字幕不是仪表盘，整体缩放换来的信息量更少。只放大文字。
- 不引第三方颜色库：只用到相对亮度与两个颜色的比值，公式二十行，加一个依赖换不来什么。
- 不改 `.row.dim` 的 0.25 透明度：那是「旧行渐隐」的语义，不是文字对比度不达标。

## 验收

- `npm run probe -- --overlay-a11y-probe` → 20 条断言（15 对文字全过 AA、最差一对也过、故意压暗的一对必须被点名、三档字号单调且在 240×120 最小窗口内装得下、脏值回落、状态标记齐全）。
- `npm run check:pure` → 同一批判据 + CSS 与像素表的漂移检查。
- 面板 浮层与对局 → 外观 → 字号三档按钮，点一下浮层文字整体换档，选择落盘跨启动记住。

## 后果

- 以后加一个颜色，就必须同时在 `OVERLAY_TEXT_PAIRS` 里加一行，否则探针不会替它算对比度——这一条靠评审守，代码强制不了「有人偷偷在 CSS 里写个新色」。
- 加第四档字号要先改 `FONT_SCALE` 与 `OVERLAY_FONT_SIZES`，两者不一致时探针与 `check:pure` 都会红。
- `stageLine` 的警告文案多了 `⚠ ` 前缀，任何按文本全等比较警告行的断言都要跟着改（目前没有）。
