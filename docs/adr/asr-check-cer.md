# 逐条 CER：三档不够用，训练见过的和留出没见过的必须分开报

## 背景

`asr-check-batch.md` 定下的三档（一致 / 差一点 / 明显错）能回答「现在认得我吗」，回答不了另外两个问题：

- 这一版比上一版好了多少？三档只有计数，没有量。
- 哪几句最该重录、最该改稿？三档里「明显错」可能有二十条，谁最差看不出来。

另外一件事更要紧：账本里的句子大多被某次微调吃过，模型当然认得——只报一个合计数是自欺，量不到泛化。
`splitTrainEval`（`src/shared/train/dataset.ts`，尾部 2 条进验证）已经算出了切分，比对却没用上。

## 决定

- **CER 作为唯一量纲**：`cer = 错字数 ÷ 原文字数`，分母是**归一化之后**的原文字数（标点与空白不算字）。
  跨句子长度可比，两次测量可以取合计。
- **口径一处写**：`src/shared/train/cer.ts` 同时拥有 `normalizeSpoken` / `spokenDistance` / `measureCer`。
  `src/shared/train/asr-check.ts` 不再自带归一化与距离，只保留「按 CER 定档」，两个文件不会各算一套。
- **合计不取平均**：`summarizeCer` 是总错字 ÷ 总字数。平均会让一条 3 字全错（100%）压过一条 30 字全对，
  而后者才是这批数据的主体。
- **分队列报**：`train`（被某次 run 吃过，量记忆）/ `eval`（`splitTrainEval` 的尾部，量泛化）/
  `unknown`（账本没记 run_id 的老数据）。三者分开列，`unknown` 不并进任何一边。
  切分只有调用方知道，所以 `gradeAsrCheck()` 默认给 `unknown`，由主进程按 `splitTrainEval` 覆盖——猜一个就等于把泛化数字做假。
- **排名从差到好**：`rankByCer` 按 CER 降序，同率时字数多的先（二十字错四个比五个字错一个更说明问题），
  再相同按 key，保证两次运行顺序一致。
- **改稿写回账本**（`correctAsrCheckItem`）：人在弹层里把稿子改成耳朵听到的样子，`recordDatasetTake` 写一条新修订。
  改稿既是「下次打包进训练数据的文本」，也是「下次比对的答案」，只改内存那一行等于同样的错再犯一遍。
  空白答案拒绝、与账本同文本不插新修订（修订号会虚增）。
- **回放**：复用人耳验收现成的路（`ftRecRead(group, line)` → Blob → `Audio`），不新增「播 wav」通道。

## 后果

- 面板顶部三行：训练见过 / 留出没见过 / 未记切分，各带条数、合计 CER、全对条数。
  第三行只在有数据时出现——凭空写一个「未记切分 0 条」会让人以为那是正常状态。
- 弹层默认只列不一致，可切「显示全部」；每行一个受控输入框 + 重听 + 保存答案，保存后提示写回了哪条、修订几。
- `--train-probe` 守纯口径（标点不算错、错两字 2/13、原文空、排名、两队列分开、合计、百分比格式、改稿写回的五个分支）。
- `--asr-check-live-probe`（`ci: false`）拿本机账本真跑一次，打印三个队列的 CER 与最差 12 行。
  它不进 CI：读的是本机账本与真实录音，机器上没有录音时只能报「没有可测的录音」，那不是回归信号。
- 仍然不落库：结果只在主进程内存里，关掉弹层就丢。要留证据就复制清单，或跑 live 探针。

## 仍然不做

- 不做逐字高亮 diff；不做跨轮次历史曲线（需要落库，等有人真的要对比再说）。
- 不用 CER 自动排序决定「该重录哪条」之外的任何事——不自动改稿、不自动排除数据。
